# 分析图表使用说明

写给负责某一个分析方向的同学。读完你能做三件事：把自己那部分的图重新画出来、改图的样子、知道什么时候必须回到数据库。

不需要装数据库，不需要懂 SQL，会运行一个 Python 文件就够了。

---

## 一、你拿到了什么

每个方向一个压缩包，解压后是一个文件夹：

| 方向 | 压缩包 | 运行哪个文件 | 图 | CSV |
|---|---|---|---:|---:|
| 一、RAG 与其他主题 | `01_theme_comparison.zip` | `make_figures.py` | 4 | 4 |
| 二、预印本 / 会议 / 期刊 | `02_publication_types.zip` | `make_figures.py` | 4 | 5 |
| 三、世界分布与合作 | `03_world_collaboration.zip` | `make_figures.py` | 6 | 7 |
| 四、子方向 | `04_subfields.zip` | `make_figures.py` | 4 | 6 |
| 五、国家投入 | `05_country_indicators_analysis.zip` | `country_indicators_analysis.py` | 3 | 8 |

文件夹里的东西：

```
01_theme_comparison/
├── 使用说明.md          本文件
├── README.md            这个方向每张图的说明：画的是什么、CSV 各列含义、数据坑  ← 改图前先读
├── make_figures.py      画图的代码，一张图一个函数                              ← 改图改这里
├── common.py            所有图共用的字体、颜色、标题格式
├── sql/                 取数用的 SQL，一张图一个文件
└── output/
    ├── fig1_xxx.csv     这张图用到的全部数据
    └── fig1_xxx.png     图本身，可以直接放进 PPT
```

三样东西按名字一一对应：`sql/fig1_theme_yearly.sql` 查出来的结果存成 `output/fig1_theme_yearly.csv`，
`make_figures.py` 里的函数 `fig1_theme_yearly` 读这个 CSV 画出 `output/fig1_theme_yearly.png`。

个别方向多几个文件：方向三有 `worldmap.py` 和 `geo/`（画世界地图底图用），方向四有 `subfield_rules.csv`（子方向的定义）。
方向五没有 `common.py`，所有代码都在 `country_indicators_analysis.py` 一个文件里。

---

## 二、第一次运行

1. **装 Python**（3.10 或更新）。已经装了 PyCharm 或 Anaconda 的可以跳过。
2. **解压**压缩包，放在哪里都行。
3. **装需要的包**，在终端里执行：

   ```bash
   pip install -U pandas matplotlib numpy scipy
   ```

   方向五还要多装一个：

   ```bash
   pip install -U statsmodels
   ```

4. **进入文件夹，运行**：

   ```bash
   cd 01_theme_comparison
   ```

   ```bash
   python make_figures.py
   ```

   方向五运行的是 `python country_indicators_analysis.py`。

   用 PyCharm 的话：打开这个文件夹，右键 `make_figures.py`，选 Run。

正常的输出是这样的：

```
  No project database around this folder: redrawing from output/*.csv (same as --from-csv).
01_theme_comparison
  01_theme_comparison\output\fig1_theme_yearly.png
  01_theme_comparison\output\fig2_growth_multiple.png
  ...
```

第一行不是报错。它的意思是：这个文件夹旁边没有数据库，所以直接用 `output/` 里的 CSV 重画。
这正是你需要的模式。`output/` 里的 PNG 会被重新生成，打开看一眼，和原来一样就说明环境没问题。

## 三、改图

### 先找到那张图的函数

打开 `make_figures.py`，一张图对应一个函数，函数名和图片文件名相同。想改 `fig2_growth_multiple.png`，就找 `def fig2_growth_multiple`。
改完保存，重新运行一次，图就更新了。

只想重画其中一张：到文件最底部的 `main()` 里，在其他几行前面加 `#` 注释掉。

### 常见改法

| 想改什么 | 改哪里 |
|---|---|
| 标题、副标题、图下方的灰色小字 | 函数末尾的 `C.titles(fig, "标题", "副标题", "小字")`，三段文字依次对应 |
| 图的宽和高 | `plt.subplots(figsize=(8.6, 4.8))`，单位是英寸，先宽后高 |
| 坐标轴标题 | `ax.set_ylabel("...")`、`ax.set_xlabel("...")` |
| 某条线、某类柱子的颜色 | 文件顶部的字典，如方向一的 `THEMES`、方向二的 `TYPES` |
| 图例的位置 | `C.legend(ax, loc="upper left", ...)`，可以换成 `"upper right"`、`"lower right"` 等 |
| 对数轴改成普通轴 | 删掉 `ax.set_yscale("log")` 那一行 |
| 所有图的字体、字号 | `common.py` 里的 `plt.rcParams.update({...})` |
| 所有图的配色 | `common.py` 里的 `SERIES`（八个颜色，按顺序取用） |
| 图片清晰度 | `common.py` 里 `fig.savefig(path, dpi=200, ...)` 的 `dpi` |

举个例子，把方向一图 1 的标题换掉：

```python
    C.titles(fig, "RAG among the large-model research themes",      # ← 大标题，改这一行
             "Computer-science papers per year matching ...",        # ← 副标题
             f"{C.SOURCE} {C.PARTIAL_2026}\n{THEME_NOTE}")            # ← 图下方的小字
```

**图上的文字想用中文也可以**，直接把英文换成中文即可，太长的副标题会自动换行。
在 Windows 上验证过（用的是微软雅黑）；Mac 上会自动找苹方等字体，没有实测过，
如果中文显示成方框，请告诉仓库负责人。方向五的脚本没有配中文字体，那几张图请保持英文。

**关于配色**：`SERIES` 里的八个颜色是按顺序挑过的，相邻的颜色对色弱读者也能区分。
换颜色时尽量在这八个里选，不要自己新增第九种。

### 改图上显示哪些数据

每个函数开头都有一行 `df = data.fetch("fig1_theme_yearly")`，读进来的就是对应的 CSV。
想少画几年、去掉某个国家、只留前 10 名，在这一行后面加筛选就行：

```python
    df = data.fetch("fig1_theme_yearly")
    df = df[df["year"] >= 2021]            # 只画 2021 年以后
```

CSV 里有哪些列、每列是什么意思，写在这个方向的 `README.md` 里。

### 不想写代码

`output/` 里的 CSV 可以直接用 Excel 或 Tableau 打开自己画。文件是 UTF-8 编码，Excel 双击就能正常显示。
用 pandas 读的话请加 `keep_default_na=False`，否则纳米比亚的国家代码 `NA` 会被当成空值。

## 四、什么时候必须连数据库

只改图的样子，用压缩包就够了。下面三种情况必须连上数据库重新跑：

1. **改了 `sql/` 里的查询**（比如前 15 名改成前 20 名、换一个时间范围）。SQL 要到数据库里才能执行。
2. **方向四改了 `subfield_rules.csv`**。规则是在数据库里匹配的，不重跑的话图不会变。
3. **要放进 PPT 的终稿**。课程要求分析数据只能来自数据库，所以最后交的图必须是连着数据库生成的。

两种做法，选一种：

**做法 A：把改过的文件发回给仓库负责人**，由负责人连数据库重跑。最省事。

**做法 B：自己搭数据库。** 按仓库根目录 `README.md` 的「路线 A」把数据库跑起来，然后在仓库根目录执行：

```bash
docker compose exec -T postgres psql -U scholarscope -d scholarscope < country_indicators_analysis/sql/00_add_taiwan.sql
```

```bash
uv sync
```

```bash
uv run python analysis/run_all.py
```

第一条是把台湾补进数据库（World Bank 没有台湾的记录），每台电脑执行一次即可，重复执行不会出错。
第三条一次重画方向一到四。只跑一个方向就把路径换成那个方向的脚本，例如
`uv run python analysis/03_world_collaboration/make_figures.py`；
方向五是 `uv run python country_indicators_analysis/country_indicators_analysis.py`。

在仓库里运行时默认就是连数据库的，并且会用新的查询结果覆盖 `output/` 里的 CSV。
这时如果只想重画不查库，在命令最后加 `--from-csv`。

---

## 五、改完怎么交回

把整个文件夹压缩发回即可。如果只改了一两个文件，只发这几个也行：

- 改了图的样子：`make_figures.py`（动过 `common.py` 的话一起发）
- 改了查询：对应的 `sql/*.sql`
- 改了子方向定义：`subfield_rules.csv`
- 改了说明文字：`README.md`

`output/` 里的 PNG 和 CSV 不用特意发，负责人会连数据库重新生成。

---

## 六、三条规矩

1. **不要手工改 CSV 里的数字。** CSV 是数据库查询结果的副本，下次连库重跑就会被覆盖，而且交上去的图说不清数据来源。
   想换数据就改 SQL，或者在代码里筛选。
2. **裁图时保留图下方的灰色小字。** 上面写着数据来源、采集日期和统计口径，PPT 没有口头讲解，全靠它说明。
3. **写结论前先读本方向 `README.md` 里的数据坑。** 每个方向开头都列了几条，踩中任何一条都会得出错误的结论。

## 七、常见问题

**`ModuleNotFoundError: No module named 'pandas'`（或 matplotlib、scipy、statsmodels）**
包没装上，或者装到了另一个 Python 里。重新执行第二节第 3 步；用 PyCharm 的话在它自带的 Terminal 里执行。

**`ModuleNotFoundError: No module named 'common'`**
没有在解压出来的文件夹里运行，或者只拷走了 `make_figures.py` 一个文件。`common.py` 要和它放在同一个文件夹。

**`FileNotFoundError: ... output\fig1_xxx.csv`**
`output/` 文件夹不完整。重新解压一次压缩包。

**运行了但图没变**
确认改完保存了；确认运行的是你改的那个文件夹里的文件；看一下 PNG 的修改时间是不是刚才。

**图上的字挤在一起或者被截断**
通常是改了标题长度或图的尺寸。把 `figsize` 调大一点，或者把标题写短一点。
方向三连线地图上的国名位置是手工调的，在函数里的 `place` 字典。

**这些代码在什么版本上验证过**
Python 3.13、pandas 3、matplotlib 3.11。版本旧很多时可能报错，执行第二节第 3 步的 `pip install -U` 升级即可。
